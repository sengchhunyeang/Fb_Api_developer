1How it works

The Django project calls the Facebook Graph API with a Page access token, follows the pagination until every post is loaded, and shows them on a web page and as JSON.

Facebook app→ Page permissions→ User token→ Long-lived token→ Page token (never expires)→ .env→ Django UI / API

You need

  • A Facebook account with Facebook access with full control of the Page.
  • Python 3.12+ on your computer.
  • The project folder: D:\s.chhunyeang\Personal\Webs\fb-posts

2Create the Facebook app

  1. Go to developers.facebook.com/apps and log in.
  2. Click Create App, type an app name, click Next.
  3. On the use case list (All), tick only Manage everything on your Page, click Next.
  4. Business portfolio: choose I don't want to connect a business portfolio yet → Next.
  5. Click Next through the remaining screens → Create app (enter your password if asked).

Important: the use case must be Manage everything on your Page. Apps without a Page use case cannot get Page permissions — tokens will only have public_profile.

3Add Page permissions to the app

  1. Open your app from developers.facebook.com/apps.
  2. In the left menu click Use cases.
  3. On the Manage everything on your Page card click Customize (or the ✏️ / Edit button).
  4. In the permission list click Add next to:
    • pages_show_list
    • pages_read_engagement
    • pages_read_user_content
  5. Each should show Ready for testing. Click Save if shown.

Tip: press Ctrl + F to find a permission in the long list. App Review is not needed — you are the app admin and the Page admin.

4Get a user token (Graph API Explorer)

  1. Open Graph API Explorer and refresh the page (F5).
  2. On the right, Meta App: choose your app.
  3. User or Page: choose Get User Access Token.
  4. Add a Permission: add the same 3 pages_... permissions. Remove any user_... permissions.
  5. Click Generate Access Token.
  6. In the popup click Edit previous settings (if shown), tick your Page, then Continue → Save.
  7. Copy the token from the Access Token box (starts with EAA…).

This token expires in about 1 hour. The next steps turn it into a Page token that never expires.

5Find the Page ID

Option A — on Facebook: open your Page → About → Page transparency → Page ID.

Option B — in Graph API Explorer: type the Page username and click Submit:

cdlsolutionskh?fields=id,name

Result:

{ "id": "100604454959362", "name": "CDL Solutions" }

6Make the token long-lived

  1. Open the Access Token Debugger.
  2. Paste the user token from step 4 and click Debug.
  3. Check: Type: User, Valid: True, and the 3 pages_... scopes.
  4. Scroll to the bottom and click Extend Access Token.
  5. Copy the new token text shown under the button (starts with EAA…). Debugging it should show Expires: in about 2 months.

Copy the token text, not the info table (Issued / Expires / Scopes). The info table is not a token.

7Get the permanent Page token

  1. Go back to Graph API Explorer.
  2. Paste the long-lived token from step 6 into the Access Token box.
  3. Type this request (use your Page ID) and click Submit: 
    100604454959362?fields=name,access_token
  4. Copy the access_token value from the result — this is the Page token.
  5. Check it in the Access Token Debugger: Type: Page, Expires: Never.

A Page token created from a long-lived user token never expires. Only Data Access must be renewed every 90 days — normal use renews it.

8Put the values in .env

Open D:\s.chhunyeang\Personal\Webs\fb-posts\.env and set:

FACEBOOK_PAGE_ID=100604454959362
FACEBOOK_PAGE_ACCESS_TOKEN=EAA...your Page token...
FACEBOOK_GRAPH_VERSION=v26.0
  • Token on one line, no quotes, no spaces.
  • .env is in .gitignore — never commit it.
  • Restart the server after every change to .env.

9Run the Django project

First time only

cd D:\s.chhunyeang\Personal\Webs\fb-posts
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python manage.py migrate

Every time

cd D:\s.chhunyeang\Personal\Webs\fb-posts
.venv\Scripts\python manage.py runserver

Keep this terminal open. Press Ctrl + C to stop the server.

"127.0.0.1 refused to connect" means the server is not running — start it with the command above.

12Security notes

  • The Page token and App secret are passwords — never share them in chat, email or screenshots, and never commit .env.
  • If a secret was shared, reset it: app → App settings → Basic → App secret → Reset.
  • The UI and API have no login. Add authentication before putting the site online.
  • Before deploying: set DEBUG = False, set ALLOWED_HOSTS, and use a new SECRET_KEY.
